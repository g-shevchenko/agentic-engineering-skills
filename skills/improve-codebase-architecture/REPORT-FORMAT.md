# Report formats

The skill emits two artifacts during a run: the **Phase 2 HTML report** (Greg-facing, browser-opened) and the **Phase 5 ADR** (codebase-resident). Both have strict formats.

---

## Phase 2 — HTML candidate report

### File location

```
$TMPDIR/architecture-review-<ts>.html
```

Where `$TMPDIR` resolves to `/tmp` on Unix, `%TEMP%` on Windows. Open with:

```bash
# macOS
open "$TMPDIR/architecture-review-<ts>.html"
# Linux
xdg-open "$TMPDIR/architecture-review-<ts>.html"
# Windows (Bash)
start "$TMPDIR/architecture-review-<ts>.html"
```

### Mandatory cards

- **Top recommendation** section above all candidates
- 3-7 candidate cards (more is noise; fewer means run again on broader scope)
- Each card has: name, badge, files, blast radius, effort, risk, Problem, Solution, Benefits, Mermaid diagram, deletion test result

### Style

- Tailwind utility classes (CDN, no build step)
- Mermaid v10 ESM CDN for diagrams
- `color-scheme: light dark` for dark-mode compatibility
- Self-contained — works offline after first load (Mermaid is the only true network dep)

### Anti-patterns

- ❌ Local file paths in URLs (use repo-relative)
- ❌ Greg's name / personal info / API keys in the HTML
- ❌ Auto-execute JavaScript beyond Mermaid init
- ❌ External CSS / fonts beyond Tailwind CDN

## Phase 5 — ADR format

Per Michael Nygard ADR style. File: `docs/adr/NNNN-<slug>.md`.

```markdown
# ADR-NNNN: <Title — verb-noun, e.g. "Extract validation as pure function from UserService">

**Status:** Accepted
**Date:** 2026-MM-DD
**Run:** improve-architecture run <ts>
**PR:** <PR url>

## Context

What was the situation that motivated this decision? Reference:

- The friction surfaced in Phase 1 (link to .agent/improve-runs/<ts>/phase1-friction.json)
- The candidate card from Phase 2
- The 3 designs explored in Phase 3 (link to phase3-design.md)

Use domain vocabulary from CONTEXT.md.

## Decision

What did we decide? State the interface change in 2-3 sentences. Include:

- The new interface (types, methods, ordering, error modes)
- The new module boundary
- What stays the same

## Consequences

### Positive
- ...
- ...

### Negative / trade-offs
- ...
- ...

### Neutral
- ...

## Alternatives considered

Briefly mention the 2 alternatives from Phase 3 design conversation.

### Alternative A — <name>
Why not chosen: ...

### Alternative B — <name>
Why not chosen: ...

## Measurement

Snapshot Δ from Phase 6:

| Metric | Before | After | Δ |
|---|---|---|---|
| Interface LOC | <n> | <n> | <n> |
| Caller imports of internals | <n> | <n> | <n> |
| Cyclomatic of interface | <n> | <n> | <n> |
| Test coverage of interface | <n>% | <n>% | <n>pp |

Link to `.agent/improve-runs/trend.jsonl` for trend.
```

### ADR numbering

Find next free number:
```bash
ls docs/adr/ 2>/dev/null | grep -oE '^[0-9]+' | sort -n | tail -1
# If output is "0042", new ADR is 0043
```

Pad to 4 digits.

### Lazy creation

If `docs/adr/` doesn't exist yet:
```bash
mkdir -p docs/adr
cat > docs/adr/README.md <<'EOF'
# Architectural Decision Records

Format: Michael Nygard ADR style. See ADR-0001 for the meta-decision.
EOF
```

## CONTEXT.md format

Lazy-created if missing. Lives at repo root or scope root (`<scope>/CONTEXT.md`).

```markdown
# Domain Vocabulary

> Maintained by improve-codebase-architecture skill.
> Add a term when a deepening introduces a new domain concept.

## Refresh Window

The bounded interval during which a `KeyMaterial` lease may be re-issued without rotating the underlying secret. See ADR-0042.

## Quiescence Period

...
```

### Maintenance discipline

- One term per heading
- One-sentence definition tied to how it's used in THIS codebase, not a generic dictionary entry
- Reference the ADR that introduced the term, when there is one
- Remove terms that no longer appear in the codebase (the skill's Phase 6 measurement can flag this)
